# Incident Response Framework

A formal Incident Response Plan (IRP) for handling network intrusions in a healthcare environment, structured on the NIST 800-61 incident response lifecycle and aligned with HIPAA Security Rule requirements.

## Purpose

Healthcare organizations handling protected health information (PHI) need a documented, repeatable process for responding to security incidents — both to contain damage and to meet regulatory obligations. This plan defines that process end to end, written so that technical responders and management can both act from it.

## Lifecycle Phases

- **Preparation** — Roles, responsibilities, tooling, and readiness requirements defined before an incident occurs.
- **Detection & Analysis** — Identification and verification of suspicious activity, with severity classification criteria.
- **Containment** — Short-term and long-term isolation of affected systems to prevent lateral movement.
- **Eradication** — Removal of the threat and closure of the vulnerability that allowed it.
- **Recovery** — Restoration of services with validation that systems are clean before returning to production.
- **Post-Incident Review** — Lessons learned and process improvements fed back into the preparation phase.

## Key Components

- Severity classification tiers governing response urgency and escalation
- Defined escalation paths and notification chains
- Evidence handling and chain-of-custody requirements
- HIPAA breach notification timelines mapped to incident severity
